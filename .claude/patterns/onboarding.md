# Pattern — Onboarding

Amener un nouvel utilisateur à sa première valeur, sans le submerger.

## Quand l'utiliser
Première prise en main, configuration initiale minimale, activation.

## Quand ne pas l'utiliser
Utilisateur récurrent (ne pas re-forcer) ; configuration exhaustive (→ `settings.md`).

## Structure recommandée
Un concept à la fois → progression claire → possibilité de passer/reporter → première action
concrète menant à la valeur. Souvent un `wizard.md` léger ou une checklist d'activation.

## Hiérarchie des informations
Prioriser le « temps jusqu'à la première valeur ». Accueillir sans submerger ; orienté action.

## États indispensables
non commencé · en cours (progression) · étape complétée · passé/reporté · terminé ·
reprise plus tard (persistance) · erreur d'une étape.

## Responsive
Une étape = un écran sur mobile ; progression compacte ; action principale ancrée.

## Accessibilité
Focus déplacé à chaque étape ; « passer » toujours accessible ; progression annoncée ;
ne pas piéger l'utilisateur.

## Erreurs fréquentes
Trop d'étapes ; impossible de passer ; onboarding rejoué à chaque visite ; perte de progression.

## Anti-patterns
Tour guidé interminable ; bloquer l'accès au produit derrière un onboarding non essentiel ;
demander tout d'un coup.

## Interactions recommandées
Passer/reporter ; reprendre où on s'était arrêté ; célébrer la première réussite (feedback) ;
checklist d'activation persistante.

## Checklist
- [ ] un concept à la fois · [ ] passer possible · [ ] progression persistée · [ ] pas rejoué inutilement · [ ] focus par étape.
